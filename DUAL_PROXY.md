# Режим «Dual Proxy» (Двойной параллельный прокси) в Throne

Этот форк добавляет полноценную нативную поддержку одновременной работы **двух независимых прокси-серверов** на разных локальных портах прямо из графического интерфейса.

---

## Как это можно было сделать в оригинале?

В официальном Throne (и Nekoray) технически **тоже можно** организовать второй локальный порт, используя встроенные низкоуровневые возможности ядра:
1. Зайти в **Основные настройки** -> блок **Пользовательский инбаунд (Custom Inbound)**.
2. Вручную написать сырой JSON-фрагмент для `sing-box`, объявив второй входящий порт (например, `mixed` на порту `2081` с тегом `secondary-in`).
3. Перейти в **Настройки маршрутизации** и вручную добавить JSON-правило маршрутизации, связывающее `inbound: ["secondary-in"]` с тегом нужного аутбаунда.
4. Либо запускать два отдельных экземпляра Throne с разными флагами `-appdata` и разными портами.

---

## Почему я решил сделать нативно из коробки?

Хотя в оригинале это возможно через правку конфигурационных JSON, на практике такой подход крайне неудобен для повседневного использования. Вот почему в этом форке всё реализовано нативно на уровне ядра и UI:

### 1. Переключение сервера в 1 клик (без правки JSON)
В оригинале при желании сменить страну или сервер для второго прокси приходится снова открывать настройки, искать тег профиля в JSON и переписывать правило роутинга.  
В этом форке: **правый клик по любому профилю в списке ➔ «Сделать вторым прокси...»** — ядро перезапускается с новой конфигурацией, включающей оба прокси. **Внимание:** при смене secondary-сервера происходит полный перезапуск ядра — все активные соединения на обоих портах будут кратковременно разорваны.

### 2. Интерактивный выбор и смена порта прямо в интерфейсе
- При назначении второго прокси появляется окно выбора порта (по умолчанию `2081`, с валидацией от коллизий с портом `2080`).
- В контекстном меню есть отдельное действие **«Изменить порт второго прокси...»** для быстрой смены порта на лету.
- Порт также вынесен в интерфейс **Основных настроек** (Inbound Settings) для централизованного управления.

### 3. Полный визуальный контроль и информативность
В оригинале при ручной настройке GUI «не знает» о существовании второго прокси. В нашем форке:
- **В таблице профилей**: сразу видно роли серверов по бейджам и цветам — `[1st:2080]` (основной) и `[2nd:2081]` (второй).
- **В строке состояния внизу окна**: выводятся оба сервера, их внешние IP-адреса и страны с флагами:
  - `1st: [default] Germany (🇩🇪 Germany, Frankfurt)`
  - `2nd: Netherlands (🇳🇱 Netherlands, Amsterdam)`
  - `Mixed: 127.0.0.1:2080 | 2nd: 2081`
- Геолокация и флаг для каждого прокси определяются независимо через соответствующие порты.

### 4. Нативная поддержка в мониторе соединений (Connections)
Второй инбаунд автоматически регистрируется в системе статистики. Во вкладке **Соединения** отображаются все активные процессы, трафик, скорость и целевые хосты как для основного порта `2080`, так и для второго порта `2081`.

---

## Краткая инструкция по использованию

1. Запустите основной сервер обычным способом (клавиша **Enter** или кнопка «Запустить») — он будет слушать на порту `127.0.0.1:2080`.
2. Кликните правой кнопкой мыши по серверу, который хотите использовать параллельно, и выберите **«Сделать вторым прокси...»**:
   - Введите желаемый порт (например, `2081`).
   - Сервер будет помечен значком `[2nd:2081]`.
3. Настройте приложение (браузер, Telegram, торрент-клиент или игру) на прокси `127.0.0.1:2081` (поддерживаются протоколы SOCKS5 и HTTP).
4. Основная система и приложения используют `127.0.0.1:2080` (или системный прокси/TUN), а отдельное приложение ходит через второй сервер на `127.0.0.1:2081`.
5. Чтобы отключить второй прокси — правый клик ➔ **«Отключить второй прокси»**.

## English Summary

**Dual Proxy Mode Fork**:
While original Throne/Nekoray allows configuring secondary inbounds manually via custom JSON and route rules, it requires manual maintenance and lacks UI feedback. This fork introduces **native Dual Proxy support**:
- 1-click profile assignment from context menu (**"Set as Secondary Proxy..."**).
- Interactive port picker & runtime port change without restarting the app.
- Clear UI indicators (`[1st:2080]` and `[2nd:2081]` badges in the server table).
- Dual status display with independent IP and country flag resolution in the status bar.
- Live connections and per-process traffic tracking for both inbounds in the Connections tab.
- Persistent primary profile memory across app restarts.

---

## Известные ограничения / Known Limitations

1. **Перезапуск ядра при смене secondary**: назначение, смена или отключение secondary-прокси перезапускает sing-box целиком — все активные соединения на обоих портах кратковременно рвутся. Горячая перезагрузка без разрыва primary пока не реализована.
2. **Пользовательские правила маршрутизации не применяются к secondary-трафику**: весь трафик с порта secondary безусловно направляется в secondary-outbound. LAN bypass, adblock, GeoIP/GeoDomain-правила — всё пропускается. Если нужно направлять LAN-трафик напрямую через secondary — используйте ручные правила.
3. **Объединённый SpeedChart**: график скорости суммирует трафик обоих прокси, отдельного отображения для secondary нет.
4. **Тег в мониторе соединений**: в колонке Outbound для secondary-соединений отображается сырой тег `secondary-0` вместо имени профиля.

## Changelog

### 2026-09-16 — Bugfix Patch

**Исправленные баги:**

- 🔴 **Critical**: Удаление профиля, назначенного secondary, больше не ломает запуск ядра. Добавлена автоматическая очистка `secondary_profile_id` при удалении и защита в генераторе конфига (`generate.cpp`, `ProfilesRepo.cpp`).
- 🔴 **Critical**: Профили типа `autoselector` и `extracore` теперь заблокированы от назначения secondary — UI показывает предупреждение (`mainwindow_setup.cpp`).
- 🟠 **DNS-утечка**: DNS-запросы от secondary-трафика больше не перехватываются и не резолвятся через primary proxy. Правило `dns-hijack` теперь ограничено только `mixed-in` и `tun-in` (`generate.cpp`).
- 🟠 **Data race**: Запись `runningCountryInfo` перенесена в UI-поток, устранено undefined behavior при конкурентном доступе (`mainwindow_profile_lifecycle.cpp`).
- 🟠 **Stale callback**: Geolocation-запрос теперь проверяет, что текущая сессия не изменилась, прежде чем обновлять UI.
- 🟡 **Бейдж `[2nd]`**: больше не отображается зелёным при остановленном ядре (`ProfilesTableModel.cpp`).
- 🟡 **Коллизия портов**: при совпадении secondary и primary порта в Basic Settings порт автоматически корректируется (`dialog_basic_settings.cpp`).
- 🟡 **Raw routing**: secondary-правило теперь инжектируется даже в raw routing-профили с `preventModifications = true` (`generate.cpp`).
- 🟡 **Пустая страна**: при ошибке `ip-api.com` строка статуса больше не показывает `" , "`.
- 📝 **Документация**: убрано ложное утверждение «без разрыва основного подключения».
